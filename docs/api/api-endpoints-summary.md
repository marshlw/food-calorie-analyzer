# Сводка API-эндпоинтов — AI Healthy

Краткое описание всех HTTP-ручек. Базовый URL по умолчанию: `http://localhost:8000`.
Версионирование API — префикс `/api/v1`.

**Типы аутентификации:**
- 🔓 — без аутентификации;
- 🔑 — Bearer JWT access-токен (заголовок `Authorization: Bearer <token>`);
- 🛡 — admin-токен (заголовок `X-Admin-Token`).

## Типовые коды ошибок

| Код | Когда возникает |
|-----|-----------------|
| `400` | Невалидный ввод: дубликат email, неверный формат даты, неподдерживаемый `grant_type`/тип файла, задача не в статусе success и т.п. |
| `401` | Отсутствует/невалиден/просрочен токен; неверные учётные данные |
| `403` | Неверный `X-Admin-Token` |
| `404` | Ресурс не найден или принадлежит другому пользователю (задача, приём пищи, фидбек) |
| `413` | Загружаемый файл превышает 10 МБ |
| `422` | Ошибка валидации тела/параметров (Pydantic) |
| `500` | Внутренняя ошибка / сбой постановки задачи в очередь |

Тело ошибки в общем виде: `{ "detail": "<сообщение>" }` (для `422` — массив объектов валидации FastAPI).

## Замечания для автотестов

1. **Порядок прогона:** `register → login` (сохранить `access_token`) → защищённые ручки.
2. **Асинхронность анализа:** после `POST /analyze` задача в статусе `pending`; для проверки `success` нужен поднятый Celery-воркер + ML-провайдер, либо мокирование. Используйте polling `GET /task/{id}`.
3. **Изоляция:** негативные тесты на чужие ресурсы должны ожидать `404`, а не `403`.
4. **Upsert веса:** два `POST /profile/weight` с одной датой не создают второй записи — проверять количество в истории.
5. **Нормы КБЖУ:** появляются только при заполненных весе+росте+поле+дате рождения (см. бизнес-правила BR-01).
6. **Норма воды:** `goal_ml`/`water_target_ml` считается из веса и активности (вес × мл/кг, 30→40 по уровню активности); без веса — `null`. Учёт идёт в мл, 1 стакан = 250 мл; запись — одна на (пользователь, дата), upsert.
