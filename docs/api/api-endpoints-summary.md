# Сводка API-эндпоинтов — AI Healthy

Краткое описание всех HTTP-ручек. Базовый URL по умолчанию: `http://localhost:8000`.
Версионирование API — префикс `/api/v1`.

**Типы аутентификации:**
- 🔓 — без аутентификации;
- 🔑 — Bearer JWT access-токен (заголовок `Authorization: Bearer <token>`);
- 🛡 — admin-токен (заголовок `X-Admin-Token`).

## Типовые коды ошибок

| Код | Когда возникает |
|-----|-----------------|
| `400` | Невалидный ввод: дубликат email, неверный формат даты, неподдерживаемый `grant_type`/тип файла, задача не в статусе success, дата в будущем и т.п. |
| `401` | Отсутствует/невалиден/просрочен токен; неверные учётные данные; токен выпущен до смены пароля (`token_version` не совпадает) |
| `403` | Неверный `X-Admin-Token`; невалидная/просроченная подпись ссылки `/uploads/...` |
| `404` | Ресурс не найден, принадлежит другому пользователю, или admin-токен не настроен (маскирует сам факт наличия admin-API) |
| `409` | Конфликт уникальности (например, повторная дата в `PUT /profile/weight/{id}`) |
| `413` | Загружаемый файл превышает 10 МБ |
| `422` | Ошибка валидации тела/параметров (Pydantic) |
| `500` | Внутренняя ошибка / сбой постановки задачи в очередь |

Тело ошибки в общем виде: `{ "detail": "<сообщение>" }` (для `422` — массив объектов валидации FastAPI).

## Замечания для автотестов

1. **Порядок прогона:** `register → login` (сохранить `access_token`) → защищённые ручки.
2. **Асинхронность анализа:** после `POST /analyze` задача в статусе `pending`; для проверки `success` нужен поднятый Celery-воркер + доступный ML-провайдер (по умолчанию Yandex Cloud, см. [архитектуру](../architecture/architecture.md)), либо мокирование. Используйте polling `GET /task/{id}`.
3. **Изоляция:** негативные тесты на чужие ресурсы должны ожидать `404`, а не `403`.
4. **Upsert веса:** повторный `POST /profile/weight` на ту же дату обновляет запись (см. `PUT /profile/weight/{id}` для явного редактирования по id) — проверять количество в истории.
5. **Нормы КБЖУ:** появляются только при заполненных весе+росте+поле+дате рождения (см. бизнес-правила BR-01), либо переопределены полями `custom_*` в профиле.
6. **Норма воды:** `goal_ml`/`water_target_ml` считается из веса и активности; без веса — `null`. Учёт идёт в мл, 1 стакан = 250 мл; запись — одна на (пользователь, дата), upsert.
7. **AI-советчик и штрих-коды** обращаются к внешним сервисам (LLM, Open Food Facts) — в CI их стоит мокировать или проверять только контракт ответа (структуру), а не конкретный текст совета.
8. **OpenAPI-схема:** статическая копия — [swagger.yaml](swagger.yaml); машиночитаемый контракт также доступен на живом сервере по `/openapi.json`, интерактивный Swagger UI — по `/docs` (оба — только если `ENABLE_DOCS=true`, в проде отключены).

См. также: [postman-collection.json](postman-collection.json), [swagger.yaml](swagger.yaml), [бизнес-правила](../requirements/business-rules.md), [модели данных](../requirements/data-models.md).
