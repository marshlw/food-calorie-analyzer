# Нефункциональные требования — AI Healthy

Идентификатор требования: `NFR-<КАТЕГОРИЯ>-<номер>`.

---

## 1. Безопасность (SEC)

| ID | Требование |
|----|-----------|
| NFR-SEC-01 | Аутентификация на основе JWT. Используются два типа токенов: `access` (тип `access`) и `refresh` (тип `refresh`); тип проверяется при декодировании. |
| NFR-SEC-02 | Время жизни access-токена — 30 минут (`ACCESS_TOKEN_EXPIRE_MINUTES`), refresh-токена — 7 дней (`REFRESH_TOKEN_EXPIRE_DAYS`). |
| NFR-SEC-03 | Токены подписываются алгоритмом HS256 (`SECRET_KEY`). Просроченный или невалидный токен → `401` «Could not validate credentials». |
| NFR-SEC-04 | Пароли хранятся в виде bcrypt-хэшей; в открытом виде не сохраняются и не возвращаются API. Пароль усекается до 72 байт (ограничение bcrypt). |
| NFR-SEC-05 | Защищённые ресурсы доступны только владельцу данных (изоляция по `user_id` для задач, дневника, фидбека). |
| NFR-SEC-06 | Admin-эндпоинты защищены статичным секретом `X-Admin-Token` (`ADMIN_TOKEN`), отдельным от пользовательской аутентификации. |
| NFR-SEC-07 | Загружаемые файлы валидируются по расширению, MIME/формату изображения (JPEG/PNG/WEBP) и размеру; EXIF удаляется при обработке. Имя файла на диске генерируется как UUID (защита от path traversal). |
| NFR-SEC-08 | CORS ограничен явным списком разрешённых origin'ов; запросы с других доменов блокируются браузером. |
| NFR-SEC-09 | Внутренние ошибки не раскрывают трассировку: непредвиденные исключения возвращают `500` с обобщённым `{"detail": "Internal server error"}`. |

## 2. Производительность и масштабируемость (PERF)

| ID | Требование |
|----|-----------|
| NFR-PERF-01 | Анализ изображений выполняется асинхронно через очередь Celery + Redis; HTTP-запрос на загрузку не блокируется временем работы ML-модели. |
| NFR-PERF-02 | Тайм-аут обращения к ML-провайдеру — 45 секунд (`MODEL_TIMEOUT_SECONDS`), с ретраями (`MODEL_RETRY_ATTEMPTS=2`) и экспоненциальной задержкой. |
| NFR-PERF-03 | Результаты анализа кэшируются в Redis на 24 часа (`CACHE_TTL`) по хэшу изображения, чтобы исключить повторный вызов модели для идентичных фото. |
| NFR-PERF-04 | Списочные эндпоинты поддерживают пагинацию (`limit`/`offset`): задачи (по умолчанию 50), фидбеки (по умолчанию 100). |
| NFR-PERF-05 | Максимальный размер загружаемого изображения — 10 МБ; изображения ресайзятся (до 1600 px) перед обработкой. |

## 3. Надёжность и отказоустойчивость (REL)

| ID | Требование |
|----|-----------|
| NFR-REL-01 | Сбой постановки задачи в очередь переводит её в статус `failure` с текстом ошибки и удаляет загруженный файл; пользователю возвращается `500`. |
| NFR-REL-02 | Поддерживается мульти-провайдерный роутинг ML-моделей (`yandex`, `gemini`, `deepseek`, `ollama`) с cooldown при сбоях провайдера (`MODEL_COOLDOWN_SECONDS=300`). |
| NFR-REL-03 | Схема БД проверяется и достраивается при старте (`ensure_schema`): `create_all` + добор недостающих колонок профиля (т.к. `create_all` не выполняет ALTER существующих таблиц). |
| NFR-REL-04 | Справочник продуктов (КБЖУ на 100 г) засевается идемпотентно при старте приложения. |
| NFR-REL-05 | Внешние ресурсы (HTTP-клиент, Redis) инициализируются при старте и корректно закрываются при остановке приложения. |

---

## 4. Совместимость и переносимость (COMPAT)

| ID | Требование |
|----|-----------|
| NFR-COMPAT-01 | Бэкенд — Python 3 / FastAPI, хранилище — PostgreSQL, очередь/кэш — Redis. Развёртывание через Docker / docker-compose. |
| NFR-COMPAT-02 | Эндпоинт `/api/v1/login` принимает тело как `application/json`, так и `application/x-www-form-urlencoded` (fallback) — совместимость с OAuth2-клиентами. |
| NFR-COMPAT-03 | Фронтенд — React (Vite, TypeScript) c PWA service worker; обслуживается статикой из того же приложения. |
| NFR-COMPAT-04 | API версионируется префиксом `/api/v1`. |

---

## 5. Наблюдаемость (OBS)

| ID | Требование |
|----|-----------|
| NFR-OBS-01 | Каждый HTTP-запрос логируется через middleware: метод, путь, статус-код, длительность. |
| NFR-OBS-02 | Неуспешные попытки входа логируются (без раскрытия пароля). |
| NFR-OBS-03 | Сбои инициализации/обучения/постановки задач логируются на уровне WARNING/ERROR, не приводя к падению старта приложения. |

---

## 6. Удобство тестирования (TEST)

| ID | Требование |
|----|-----------|
| NFR-TEST-01 | API задокументировано в OpenAPI 3.0 (`/docs/api/swagger.yaml`) и доступно интерактивно по `/docs` (Swagger UI FastAPI). |
| NFR-TEST-02 | Предоставляется Postman-коллекция, полностью соответствующая спецификации, с переменными окружения (`base_url`, `access_token`, и т.д.). |
| NFR-TEST-03 | Базовый URL по умолчанию для локального запуска — `http://localhost:8000`. |
